Overview

48-Hour DevSecOps Security Sprint

Modern web applications are increasingly targeted through vulnerabilities arising from improper access control, object-level authorization flaws, and weak request integrity — not cryptographic failures.

This project presents a comprehensive security hardening workflow applied to a Flask-based To-Do application, simulating a real-world secure SDLC within a time-constrained agile sprint.

Elicited Requirements

Security Requirements (SR-1 → SR-6)

SR-1

Enforce object-level authorization on every task operation by strictly binding database queries to the authenticated user's identity.

SR-2

Protect all unsafe HTTP methods (POST, PUT, DELETE) with cryptographic CSRF tokens validated server-side prior to processing.

SR-3

Inject anti-clickjacking HTTP headers (X-Frame-Options and Content-Security-Policy) on all server responses.

SR-4

Harden session cookie attributes, specifically enforcing the SameSite attribute to mitigate cross-site request flooding.

SR-5

Integrate automated SAST and DAST into the Software Development Lifecycle.

SR-6

Implement a CI/CD release gate that automatically fails the pipeline if critical/high-severity findings are detected.

Findings

Vulnerability Findings

6.5

IDOR

Insecure Direct Object Reference

Direct object references in URL routing (/tasks/<id>/edit) without ownership verification. Attacker manipulates integer IDs to access foreign records.

EXPLOITATION

User A POSTs to /tasks/5/edit — modifies User B's data with zero technical complexity.

8.8

CSRF

Cross-Site Request Forgery

Browser auto-includes session cookies for cross-origin POST requests. No distinction between legitimate and forged form submissions.

EXPLOITATION

Hidden form on attacker page auto-submits DELETE — victim's session executes unauthorized destruction.

5.4

Clickjacking

UI Redress Attack

Browsers allow pages in iframes across origins. Attacker overlays deceptive UI on transparent framed legitimate app.

EXPLOITATION

"Click to Win" button aligned over hidden Delete Task button — victim clicks unknowingly.

Implementation

Code-Level Mitigations

IDOR Mitigation — User-Scoped Query
# app/routes/tasks.py
from flask_login import current_user
from app.models import Task

def _get_user_task_or_404(task_id):
  """Returns 404 if task belongs to another user."""
  return Task.query.filter_by(
    id=task_id,
    user_id=current_user.id
  ).first_or_404()
CSRF Mitigation — Synchronizer Token
# app/__init__.py
from flask_wtf.csrf import CSRFProtect
csrf = CSRFProtect()

def create_app(config):
  app = Flask(__name__)
  csrf.init_app(app)
  return app

<!-- Jinja2 Template -->
<input type="hidden" name="csrf_token"

Clickjacking Prevention — Security Headers
# app/__init__.py
@app.after_request
def add_security_headers(response):
  response.headers["X-Frame-Options"] = "DENY"
  response.headers["Content-Security-Policy"] \
    = "frame-ancestors 'none'"
  response.headers["X-Content-Type-Options"] \
    = "nosniff"
  return response
Session Hardening — Cookie Attributes

SESSION_COOKIE_SAMESITE = "Lax"
